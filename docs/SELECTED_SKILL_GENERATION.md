AI는 recipe·이름·짧은 보조효과 목록·발동 조건·상대 강도를 작성합니다. 앱이 엔진의 단위·대상·기본값·범위를 구성하고 역할별·세대별 효과 상한을 강제합니다. 자세한 현재 동작은 [ROLE_FIRST_SKILL_GENERATION.md](ROLE_FIRST_SKILL_GENERATION.md)를 참고하세요. 아래는 기존 편집기·중단 처리의 배경 설명입니다.

# 2026.10.16.6 — 선택한 스킬 생성과 실패 복구

## 편집 및 저장 범위

편집창에서 선택한 패시브/액티브/궁극기 하나만 AI로 생성하고 검사·저장합니다. 다른 두 슬롯의 저장된 스킬은 연계 참고와 시뮬레이션에 사용하지만 수정하지 않습니다. 다른 탭에 미저장 입력이나 잘못된 수치가 있어도 해당 초안을 덮어쓰거나 선택 슬롯 저장을 막지 않습니다. 설계 JSON 가져오기도 선택 슬롯에만 적용합니다. 새 캐릭터를 처음 만들 때 세 스킬을 초기화하는 별도 경로는 유지합니다.

## 기존 실패 경로와 수정

이전 편집기는 세 슬롯 전체와 많은 선택 필드를 AI가 동시에 출력하도록 요구했습니다. 허용 범위로 보정할 수 있는 숫자도 원본과 정규화 값이 다르면 실패시켰고, 일부 공급자의 `{code:'invalid_json'}` 오류를 메시지에 JSON이 없다는 이유로 재시도하지 못했습니다. 밸런스 조정 역시 전체 스킬셋을 수정했습니다.

현재는 AI에게 선택한 한 스킬의 컨셉(plan)·효과 목록·간단한 수치를 요청하고, 앱이 다음을 수행합니다.

- 코드 이름과 카탈로그의 한국어 이름, 알려진 대상/효과 별칭을 연결합니다. 지원하지 않는 신규 규칙은 만들지 않습니다.
- 선택 필드 누락, 숫자 문자열, %, 초/회 단위 문자열을 처리하고 기본값·허용 범위·정수 조건을 적용합니다. 자동 보정한 항목은 기록에 남깁니다. 수동 입력은 이 보정 경로를 거치지 않습니다.
- 자기 슬롯을 복사하는 교체 효과 등 보정 가능한 설정은 정리합니다. 지원하지 않는 효과, 잘못된 조건, 생성자가 없는 표식/모드/기록 의존성은 실패 사유로 표시하고 다시 요청합니다.
- 정상 응답은 선택 슬롯만 조정하는 balanceSlot으로 검사합니다. 모의 전투는 기존 엔진·27개 비교 조건을 사용하고 최대 3회 수치 조정을 수행합니다. 다른 슬롯과 저장 데이터는 바꾸지 않습니다. 목표 밸런스 밖이어도 검사 결과를 명확히 표시합니다.

## 진행, 재시도와 중단

상태에 1~7단계와 경과 시간을 표시합니다: 컨셉/연계 확인 → AI 설계 응답 대기 → JSON 해석 → 효과/대상/조건 연결 → 수치 보정 → 연계/유효성 확인 → 모의 전투. 서버 내부의 사고 과정을 알 수 있다고 표시하지 않고 응답 대기라고 명시합니다. 모의 전투는 조정 회차와 비교 조건 진행 수를 표시합니다.

모든 시도별 실패, 자동 보정, 복구 초안 여부와 검사 실패를 펼쳐 읽을 수 있습니다. 실패 뒤 성공해도 해당 실행의 이전 실패 사유를 유지합니다. 재생성은 최초 1회 + 최대 5회(총 6회)입니다. 신규 편집기 요청은 AI 호출기의 숨은 JSON 재요청·자동 공급자 전환·길이 제한 이어쓰기를 사용하지 않고 생성기가 재시도를 관리합니다. 인증/모델/잔액/권한/거절 오류는 즉시 중단합니다. 통신·시간 초과·요청 제한 등은 최대 3회 요청 후 중단합니다. 요청 1회의 앱 대기 제한은 90초입니다.

6회 응답 형식/설계를 완성하지 못하면 앱이 남은 유효 컨셉과 지원 효과로 **복구 초안**을 만들고 검사합니다. 이것을 AI 생성 성공으로 표시하지 않으며 사용자가 확인하고 저장해야 적용합니다. 통신·인증 오류를 복구 초안으로 감추지 않습니다. 외부 AI의 응답 품질이나 통신 성공을 보장하는 기능은 아닙니다.

중단 버튼은 비활성 편집 영역 밖에 있습니다. 창 닫기나 다른 편집창 열기도 실행을 취소합니다. AI 응답 대기, 재시도 대기, 대기열, Worker 및 메인 스레드 검사 대체 경로 모두 취소를 처리합니다. 취소 후 늦은 응답은 초안/캐릭터에 반영하지 않습니다. 브라우저 fetch에는 AbortSignal을 전달합니다. CapacitorHttp에는 호출 취소 API가 없어 앱의 대기와 후속 처리를 즉시 중단하지만 이미 전송된 서버 요청 자체는 완료될 수 있습니다.
