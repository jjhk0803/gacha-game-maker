# 전투 연출 개선 — 2026.10.17.1

## 이번 버전에서 바뀐 점

1. 스킬 설명과 숫자 입력칸은 반올림한 정수로 표시합니다. 예를 들어 435.599999999%는 436%로 보입니다. 기존에 저장된 소수점 값은 단순히 화면을 열거나 다른 항목을 수정하는 것만으로 바뀌지 않습니다. 해당 숫자 칸을 직접 수정했을 때 새 입력값을 적용합니다. 예전 형식의 공격력 배율도 편집기에서는 %로 표시합니다(2.13배 → 213%). 내부 피해 계산·밸런스 시뮬레이션의 정밀도는 유지합니다.
2. 기본 배속의 전투 갱신 간격을 170ms에서 230ms로 늘렸습니다. 같은 전투 시간이 흐르는 속도가 약 26% 느려집니다. 2배속·3배속은 새 기본 속도의 2배·3배입니다. 공격속도 스탯이나 모의전투 결과를 바꾸는 조정은 아닙니다.
3. 스킬 편집 → ‘발동 제한 · 연출 설정’에서 12종 이펙트, 12색 팔레트와 직접 색상 선택을 사용할 수 있습니다. ‘이펙트 미리보기’는 실제 전투와 같은 연출기를 사용합니다.
4. 궁극기 SP는 궁극기 버튼의 하단 안쪽에 금색으로 겹쳐 표시합니다. 아래의 액티브 상태 문구와 위치·색상을 구분했습니다.
5. ‘일정 시간마다’ 액티브는 첫 발동 대기·재사용 대기·재발동 최소 간격을 반영한 남은 시간을 초 단위로 올림 표시합니다. 공격 횟수형 액티브는 기존의 횟수 표시를 유지합니다. 행동 제한이나 효과 조건에 따라 0초여도 실제 사용이 지연될 수 있습니다.
6. 궁극기 컷인은 약 0.98초 동안 빠르게 진입하는 띠, 확대되는 캐릭터 그림, 움직이는 스킬 이름과 속도선으로 표시합니다.
7. 컷인 재생 중에는 다음 전투 시뮬레이션 갱신을 중지합니다. 전투 시간·쿨타임·SP 자연 회복이 함께 멈추며, 컷인 종료 후 대기 중인 효과 연출을 재생합니다. 같은 갱신에 여러 궁극기가 발생하면 순서대로 컷인을 재생합니다. 마지막 적을 쓰러뜨렸을 때도 투사체 도착과 짧은 타격 연출을 보여준 뒤 결과 화면으로 넘어갑니다. 연습장의 수동 일시정지 상태는 별도로 유지합니다. 컷인을 끄면 이 정지도 발생하지 않습니다.

## 연출 종류

| 연출 | 보이는 방식 |
|---|---|
| 빛줄기 | 시전자와 대상 사이에 짧게 뻗는 빔 |
| 타격 파동 | 대상 중심에서 퍼지는 원과 파편 |
| 회복 광휘 | 대상 위로 떠오르는 회복 십자와 광환 |
| 보호막 | 대상 중심의 방패 모양 광막 |
| 마력탄 | 대상까지 이동하는 구체와 잔광 |
| 화살 | 대상까지 날아가는 화살 |
| 총탄 | 빠르게 이동하는 짧은 탄환 |
| 화염구 | 살짝 휘어 날아가는 불덩이 |
| 빙결창 | 날아가는 얼음 결정과 교차 타격 |
| 번개 | 대상 위로 떨어지는 번개 |
| 참격 | 대상 위치를 가로지르는 두 줄기 참격 |
| 별빛 폭발 | 날아가는 별과 방사형 별 조각 |

총·활·마법 계열 캐릭터와 지원형의 일반 공격에는 이동 투사체를 사용합니다. 무기 이름과 설명·캐릭터 컨셉을 참고하며, 근접 공격은 짧은 전진 동작을 사용합니다. AI 스킬 생성도 무기·속성·회복/보호 역할에 맞는 연출을 기본으로 선택합니다. 기존 스킬의 저장된 연출은 유지합니다. 독 등 지속 피해는 매번 새 투사체를 날리지 않습니다.

기기에서 동작 줄이기를 설정한 경우 투사체 이동을 생략하고 대상의 짧은 효과를 유지합니다. 연출용 노드 수를 제한하고 종료 후 제거합니다.

## 설치·GitHub 반영

- 기존 ‘메이커 전투 테스트’ 앱 위에 APK를 설치합니다. 패키지와 서명은 이전 테스트 앱과 동일하며 Android 버전 코드는 11 → 12입니다. 원본 공식 앱과는 별개입니다.
- 소스 ZIP을 풀어 **안쪽 프로젝트 폴더의 내용**을 비공개 저장소 루트에 반영합니다. 상위 포장 폴더째 올리지 마세요.
- 자동 패치에 쓰이는 핵심 파일은 `www/index.html`과 `version.json`입니다. 소스와 함께 두 파일을 같은 커밋으로 반영하세요. APK만 릴리스 첨부 파일에 올리는 것으로 웹 자동 패치가 배포되지는 않습니다.
- 비공개 패치 대상은 기존 `example/maker-combat-test`의 `main` 브랜치를 유지합니다.
- 다음 APK를 직접 만들 때는 `version.json`의 `androidVersionCode`를 이전 APK보다 큰 값으로 올리거나 빌드 스크립트의 `--version-code`를 지정합니다. 날짜의 마지막 번호와 Android 업데이트 번호를 분리했습니다.

## 검증 범위

자동 검사는 기존 전투·생성·저장·업데이트 흐름과 새 연출의 DOM, 이동 애니메이션 좌표·색상·정리, 정수 표시 시 원본 값 보존, SP 위치, 액티브 대기 시간, 컷인 중 정지와 재개·연속 재생·화면 이탈을 확인합니다. APK 서명·패키지·버전·웹 파일 일치와 원본 네이티브 코드를 별도로 확인합니다. 실제 Android 기기의 화면과 성능, 실제 AI API의 응답은 이번 환경에서 확인하지 않았습니다.
