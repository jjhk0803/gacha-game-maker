- 일반 전투의 BURST 게이지·버튼·일제 공격을 제거했습니다.
- 기존의 공격 턴 감소식 단일 스킬 대신 패시브 / 강제 액티브 / 수동·자동 필살기를 사용합니다.

- AI 생성은 규칙 검사 → 수치 예산 제한 → 내부 전투 비교 → 제한 횟수 내 조정 순서입니다. 잘못된 개별 스킬 생성 응답은 오류를 보여주고 기존 캐릭터를 유지합니다. 전체 캐릭터 생성 중 잘못된 스킬은 기본 구성으로 대체하고 안내를 남깁니다.
- 캐릭터가 여러 명 생성되더라도 시뮬레이터 작업은 한 개씩 실행합니다. Worker 사용이 불가능하면 나눠 실행하는 대체 경로를 사용합니다.
- 기존 심연탐사 **카드 전투**의 `c.skill`과 카드 엔진은 유지합니다. 이전 저장의 자동전투형 심연탐사는 원래 공통 전투 화면을 사용하므로 새 엔진을 사용합니다.

## 스킬 규칙

각 슬롯은 이름, 설명, 첫 사용 대기, 재사용 대기, 효과 1~4개를 가집니다.
각 효과는 종류, 대상, 수치, 지속 시간, 확률, 최대 중첩, 추가 조건을 가집니다.

| 슬롯 | 발동 방식 | 재사용 범위 |
|---|---|---|
| 패시브 | 전투 시작 / 일정 시간 / 자신의 HP 40% 이하 / 기본 공격 후 / 피격 후 / 아군 쓰러짐 | 3~30초 |
| 액티브 | 대기시간 완료 시 강제 자동 | 4~30초 |
| 필살기 | 버튼 또는 필살 자동 | 12~60초 |

기절·침묵 중에는 스킬을 사용할 수 없습니다. 기절은 기본 공격도 막습니다. 대기시간은 공격 횟수와 무관합니다.
전투는 고정 0.17초 간격으로 계산하며 배속은 실제 실행 간격만 바꿉니다. 일반 전투 제한은 게임 내 약 119초입니다.
전투 시작 패시브는 첫 대기 후 한 번 발동합니다. HP 조건 패시브는 조건이 유지되면 재사용 대기 후 다시 발동할 수 있습니다.

지원 효과 24종: 피해, 방어 무시 피해, 회복, 최대 HP 비례 회복, 보호막, 지속 피해, 지속 회복, 공격·방어·속도 증가, 공격·방어·속도 감소, 치명타 확률 증가, 받는 피해 증가·감소, 기절, 침묵, 도발, 해로운 효과 해제, 이로운 효과 해제, 흡혈 공격, 필살기 대기 단축, 부활.

- 지속 효과는 동일 시전자·슬롯·종류별로 최대 중첩을 제한하고, 초과하면 가장 오래된 것을 갱신합니다.
- 보호막 합계는 대상 최대 HP를 넘지 않습니다. 지속 피해는 기록된 공격력 기준으로 매초 HP를 직접 감소시킵니다.
- 흡혈은 실제 HP 피해의 30%를 회복합니다. 부활은 전투 중 대상당 한 번, 필살기에서만 가능합니다.
- 필살기는 필살기 대기 단축 효과를 가질 수 없습니다. 재귀적인 패시브 연쇄와 무한 행동을 제한합니다.
- 직접 공격 스킬에는 전용장비 레벨 보정이 적용됩니다. 일반 성장·소속 공격 보너스도 전투 입력 능력치에 반영됩니다.
- 보스 전술도 시간 기반으로 바뀝니다. 예전의 턴 기반 충전/속성 전환은 각각 광역 강타/방어 약화로 변경했습니다. 보스 설명과 실제 계산을 같은 규칙으로 맞췄습니다.

## 밸런스를 맞추는 기준

### 캐릭터 스킬

같은 캐릭터의 기본 구성과 새 구성을 기준 파티의 같은 자리에 교체하여 비교합니다.
레벨 1·30·70 × 적 편성 3종(일반/단독 보스/다수) × 난수 3개 = **27쌍의 비교 전투**입니다.
승패, 남은 HP 비율, 승리 시 소요 시간을 합친 점수의 비율을 사용합니다.
기준 대비 0.7~1.3 범위를 목표로 하고, 효과 수치·빈도·전체 대상 효과를 반영한 예산 제한도 적용합니다.
AI 구성은 최대 3차례 평가하면서 효과 수치를 조정합니다. 범위에 못 들어오면 강한 편/약한 편으로 표시합니다.
직접 저장한 구성은 검사만 하고 수치를 바꾸지 않습니다. 수동 편집 이후 능력치를 바꿔도 스킬을 임의 재조정하지 않습니다.

### 스테이지 적

레벨별 기준 4인 편성과 **스테이지의 적 전체**를 싸우게 합니다.
메인·이벤트 권장 기준 레벨은 `1 + 장 번호(0부터) × 7 + min(스테이지 순서, 10) × 0.6`을 반올림합니다.
훈련은 기존 훈련 권장 레벨을 사용합니다. 실제 보유 캐릭터를 강하게 만들었다는 이유만으로 적이 계속 강해지는 방식이 아닙니다.

HP·공격·방어 비율을 함께 조정하며 9단계 탐색 × 난수 8개 = 72전투로 검사합니다.
기준 승률 62.5%를 목표로, 50~75%를 목표 구간으로 봅니다. 수동 수정 적은 건드리지 않으므로 목표를 달성하지 못할 수 있습니다.
새 메인·이벤트 생성에 적용하고 기존 스테이지는 첫 전투 준비 시 또는 자동조정 버튼으로 적용합니다.

이 수치는 **초기 기준**입니다. 실제 플레이 승률, 모든 캐릭터 조합, 장비·돌파 수준, 수동 필살기의 최적 조작까지 보장하지 않습니다.
장기 플레이 데이터에 따라 기준 편성·목표 승률·효과 비용을 추가 조정해야 합니다. 레이드의 누적 HP·보상 구조는 유지하며 레이드 자체의 난도 곡선은 별도 보정하지 않습니다.

## 개발자용 재현 방법

Node.js 22 이상, Python 3, Java 17 이상을 사용했습니다. 게임 실행 자체에 npm 패키지는 필요 없습니다.

```sh
npm ci
npm run build
npm test
python -m http.server 8765
```

브라우저에서 `http://localhost:8765/www/?builtin=1`을 엽니다.
모듈을 수정했다면 `npm run build`를 다시 실행하세요. 빌드 없이 index.html만 배포하면 예전 모듈이 실행됩니다.

APK 도구:
- apktool 3.0.3: https://github.com/iBotPeaches/Apktool/releases/tag/v3.0.3
- uber-apk-signer 1.3.0: https://github.com/patrickfav/uber-apk-signer/releases/tag/v1.3.0
- 원본 APK: https://github.com/jjhk0803/gacha-game-maker/releases/tag/v2026.10.14.7

```sh
python scripts/build-android-test.py \
  --original /경로/gacha-game-maker.apk \
  --apktool /경로/apktool_3.0.3.jar \
  --signer /경로/uber-apk-signer-1.3.0.jar \
  --private-repo OWNER/YOUR_TEST_REPO \
  --build 2026.10.18.4 --version-code 31 \
  --output artifacts/maker-battle-test.apk
```

저장소에는 Android Gradle 프로젝트가 없으므로 원본 APK의 dex와 네이티브 플러그인을 유지하는 빌드입니다.
테스트 패키지 이름: `com.personal.starfallcontract.battletest`.
테스트 서명키는 도구의 공개 디버그 키이며, 공식 배포 서명으로 쓰면 안 됩니다.
